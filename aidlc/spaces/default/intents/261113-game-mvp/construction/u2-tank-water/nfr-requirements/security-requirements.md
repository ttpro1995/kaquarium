# Security Requirements — u2-tank-water

> Upstream: `functional-design/functional-spec.md` (W7–W11), `rules.md` (BR8–BR9), `requirements.md` (NFR3, NFR4, NFR5), `contract-summary.md` (C2 determinism rule, C5 validation, C6 import pipeline). Answers from `nfr-requirements-questions.md` (Q1–Q4 all A).
> Threat posture: browser-local game, no network, no auth, no PII, no secrets. The only trust boundary is the save file / species data file, both covered below.

| ID | Requirement | Source | Verification |
|---|---|---|---|
| NFR3.1 | U2 draws randomness only through `ctx.rng`; no `Math.random`, `Date.now`, or other ambient nondeterminism in systems or handlers, so seed + command sequence replays water state exactly. | NFR3 | Replay golden test: fixed seed + scripted ticks/commands match stored state. |
| NFR4.1 | Latch derivation is owned by the v1 → v2 migration (Breaking change register in `tech-stack-decisions.md`), not by load defaulting or the first tick: after checksum verification and before shape validation, the migration fills absent `prevQualityBand` (from `max(waste, nitrate)`), `overcrowdLatch` (from `bioload > volumeL`), and `tempPoorLatch` (from catalogue `tempFit < 0.5` for any fish — the boot catalogue revision is the pinned dependency). No code path after the migration may see an undefined latch. | NFR4 | v1 fixture → migrated save has all latches equal to a fresh v2 save at equal numbers (round-trip test). |
| NFR4.2 | U2 never reads raw save payloads; all Tank state enters through the C6 import pipeline (shape → version → checksum → migrate → rollback check), so a corrupt or tampered file is rejected before U2 logic runs. Prototype-pollution keys are rejected by U1's `findBannedKey` scan (`__proto__` / `constructor` / `prototype` at any depth → INVALID_SHAPE); NFR4.2 relies on that guard rather than re-stating it. | NFR4 | Corrupt-import suite rejects without touching the current save; banned-key fixture rejected. |
| NFR4.3 | Bounded import barrier (owner: U1 kernel, required input from this unit): size-gate the raw text BEFORE `JSON.parse` (reject when `text.length` exceeds 2 MB — a huge payload must never reach the parser); after checksum, before migrate, reject INVALID_SHAPE when counts exceed fish 1000 / cohorts 500 / orders 6 / notifications 100; after migrate, validate required Tank structure (latch fields present with types, equipment structured, chemistry in range waste/nitrate 0–100 and tempC 10–35) and `Fish.genome` is-record (U3 NFR4.1 consumer), plus the U4 NFR4.2 feeding bounds (stack/program checks, 24-stack cap) and the U5 NFR4.2 breeding bounds (pair/cohort field checks, pairs ≤ 500), so a hand-stamped v2 save with missing fields or a non-record genome fails instead of loading undefined latches. A recomputed-checksum payload with inflated counts or out-of-range chemistry therefore never reaches the O(fish + cohorts) scan, including across 192 catch-up ticks. | NFR4 | Oversize-text/over-count/out-of-range/hand-stamped-v2 fixtures rejected with named errors; current save untouched. |
| NFR5.1 | Water logic is test-first (TDD) with the 80% line-coverage floor and CI gate; latch edge-transitions (band flips, overcrowd open/re-arm) carry boundary tests. | NFR5 | Coverage report + CI block on failure. |

Out-of-scope notes (explicit): the C6 checksum detects corruption and casual editing, not deliberate cheating (public algorithm, player-side app) — NFR4.3 bounds what a recomputed-checksum payload can do; species JSON is validated at build/dev-boot and excluded (never crashed) in production per C5, so data files are never executed as code.
