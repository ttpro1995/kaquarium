# Security Requirements — u4-feeding

> Upstream: `functional-design/functional-spec.md` (W16–W20), `rules.md` (BR12–BR13), `requirements.md` (NFR3, NFR4, NFR5), `contract-summary.md` (C2 determinism rule, C6 import pipeline). Answers from `nfr-requirements-questions.md` (Q1–Q4 all A).
> Threat posture: same as U2/U3 (browser-local, no network/auth/PII/secrets). Feeding-specific surfaces: food purchase money path (C2 purchase-path exception), expiry-gated usability, auto-feeder device unlock.

| ID | Requirement | Source | Verification |
|---|---|---|---|
| NFR3.1 | Feeding determinism: the auto-feeder keys off the absolute game hour (`gameDay × 24 + gameHour`) with `lastRunHour` init at program creation (first run after one full interval, never a backlog run); day-idempotency counters key off `gameDay`; no wall-clock reads anywhere in the feeding path (any future draw uses `ctx.rng`). Replay reproduces every feed, expiry sweep, and auto-feed event. | NFR3 | Golden replay test with a scheduled program + expiry crossing. |
| NFR4.1 | Feeding-state migration, single owner: the v1 → v2 migration adds the absent feeding shape — `state.feeding` schedule section, `FoodItem.acquiredDay/target` defaults, cohort `firstFoodDays = 0` / `lastFryFedDay = 0` (register rows amended into the U2 breaking-change register; no load-defaulting path). | NFR4 | v1 fixture → migrated feeding state equals a fresh v2 save; absent-field fixtures rejected-or-filled per register, never undefined at runtime. |
| NFR4.2 | U4 never reads raw save payloads; all feeding state enters through the C6 import pipeline plus the U2-owned NFR4.3 bounded import barrier, with these explicit U4 inputs to that barrier (owner: U1 kernel; enforced post-migration, pre-runtime, INVALID_SHAPE on violation): per-stack — known kind (flakes/pellets/liveFirst), qty integer ≥ 1, acquiredDay integer ≥ 1 (game day counts from 1); per-program — intervalHours ≥ 1, portions ≥ 1, fish-target foodKind; food stacks ≤ 24 import cap (BR12.2 appends one stack per buy, so runtime count is unbounded by construction — the sweep stays O(stacks) with a nanosecond constant; the cap covers hand-stamped saves). Food-purchase money handling follows the C2 purchase-path exception (validate-first, deduct-or-reject atomic). | NFR4 | Import suite rejects malformed feeding state without touching the current save, including hand-stamped v2 feeding fixtures (zero intervalHours, negative qty, acquiredDay 0, unknown kind, 25th stack). |
| NFR5.1 | Feeding logic is test-first (TDD) with the 80% line-coverage floor and CI gate; portion/expiry/idempotency/schedule paths carry boundary tests. | NFR5 | Coverage report + CI block on failure. |
