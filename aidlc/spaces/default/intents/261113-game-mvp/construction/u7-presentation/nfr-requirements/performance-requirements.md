# Performance Requirements — u7-presentation

> Upstream: `functional-design/functional-spec.md` (W36–W49), `requirements.md` (NFR1), sim NFR splits (water 4 + fish 2 + feeding 1 + breeding 0.5 + commerce/notify 0.5 = 8 ms/frame). Answers from `nfr-requirements-questions.md` (Q1 A).

| ID | Requirement | Source | Verification |
|---|---|---|---|
| NFR1.1 | Rendering owns ≥ 12 ms of the 20 ms frame at 50 fps on the Meizu Lucky 08: 100 procedural fish sprites + boids steering + particles + clock-driven lighting in PixiJS 8. Sprite pool fixed at scene build; no per-frame allocation in the steering/ambient loop; lighting is a tint update, not a redraw. | NFR1 | Benchmark scene (100-fish save): (a) total p95 frame time ≤ 20 ms with sim at x1; (b) total p95 frame time ≤ 20 ms at x4 (4 ticks/frame worst case — the x4 gate the 12+8 split depends on; the benchmark induces the burst deterministically by queueing 4 ticks immediately before a measured frame, since a plain x4 run rarely packs a frame, plus the natural 60 s x4 soak in NFR1.2); (c) render-isolated probe with sim paused (speed 0): render-only p95 ≤ 12 ms. All on a calibrated proxy of the reference device (on-device validation at milestones); allocation probe: heap growth < 256 KB over 1000 rendered frames. |
| NFR1.2 | Sim/render handoff never blocks the frame: U7 reads via selectors on `version` bumps only. Scheduler contract (U1/U7 codegen input, recorded in C2): x1 advances 1 game-hour per real second; x2/x4 scale linearly. A 4-tick x4 burst applies within the 8 ms sim cap (C2) and never stalls the render loop — excess ticks accumulate per the C2 policy, and the HUD loading indicator (W38) surfaces backlog beyond one frame's worth; catch-up runs behind the loading state. | NFR1 | x4 soak test (100-fish save): 60 s at x4 = 240 game-hours with no player commands → version delta is exactly 240; p95 frame ≤ 20 ms, max frame ≤ 50 ms (GC allowance), zero dropped ticks. |
| NFR1.3 | Reduced-motion mode costs no more than full motion: frozen ambient layers skip their updates entirely (no hidden per-frame work). | NFR1 | p95 frame time on the benchmark scene, full vs reduced motion within 5%. |
